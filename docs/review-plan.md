# План code-review модуля src/discount.py

## 1. Цели ревью
- **Точность расчётов:** итоговая цена соответствует бизнес-правилам;
  нет ошибок округления денежных сумм.
- **Защита от фрода:** нельзя получить отрицательную цену или скидку выше
  максимальной; повтор одного промокода не даёт многократной скидки.
- **Корректность применения скидок:** порядок применения (базовая скидка,
  промокоды, уровень лояльности, ограничение 30%) зафиксирован и покрыт
  тестами.

## 2. Измеримые критерии
| Критерий | Целевое значение |
|---|---|
| Магические числа (0.85, 15000, 500 и т.д.) | 0, вынесены в именованные константы |
| Валидация входных данных (cart_sum, tier, promos) | есть, с понятными исключениями |
| Покрытие тестами | > 80% |
| Ошибки flake8 | 0 |
| Размер одного PR | не более 400 изменённых строк |
| Время ответа ревьюера | не более 2 рабочих дней |

## 3. Участники и роли
| Роль | Ответственность |
|---|---|
| Автор (разработчик) | Готовит PR, отвечает на замечания |
| Ревьюер (Tech Lead) | Проверяет логику, архитектуру, критерии из п. 2 |
| QA-инженер | Проверяет тесты и граничные случаи |
| Аналитик/владелец продукта | Подтверждает бизнес-правила скидок |

## 4. Эскалация при спорах
1. Автор и ревьюер обсуждают спорный момент в комментариях PR
   (максимум 2 итерации).
2. Если согласия нет, подключается Tech Lead для принятия решения
   в течение 1 рабочего дня.
3. Если спор касается бизнес-правил, решение принимает
   владелец продукта.
4. Итоговое решение фиксируется комментарием в PR и,
   при необходимости, в документации.
